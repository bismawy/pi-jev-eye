# Changelog

## [0.2.1] - 2026-10-14

### Fixed
- **A reviewed turn no longer loses its injected contract when routing returns early.** `before_agent_start` built the report contract after the routing branches, so three paths — the routing budget running out, no usable credential, and no available target model — returned `undefined` from a turn the operator had marked for review. The contract is now built once, before those branches.
- **`[←]` from a sub-screen keeps the cursor on the row it came from.** The root menu rebuilds its picker on every loop pass and `ListPicker` always started at row 0, so backing out of Routing (or any other screen) landed on Accounts. `pickRow` takes an initial row, the menu remembers the last one, and the picker clamps it to the row count.

### Removed
- `usdPerMTokFor` in `extensions/core.ts` and the `AccountsPicker.providers` getter, both with no callers.
- The `onBack` option on `ListPicker`/`pickRow`: the only caller never passed it, so the menu's footer advertised a back key its handler could not act on. `pickRow` also stopped returning a `"back"` value it swallowed itself.
- The unused `ctx` parameter on `refreshClefModels`, and two orphaned comment blocks in `gate.ts` and `flows.ts` that described code in other files.

### Changed
- `npm run render-check` resolves the pi-arnative footer through a relative URL and checks the export, instead of importing an absolute path from one machine. A clone without that checkout, or with one on a branch that predates the helpers, skips those assertions with a notice instead of crashing the whole command.
- `test/contract.test.mjs` reads the review contract's line threshold from `JEV_MIN_DIFF_LINES` instead of pinning the literal `10`, so changing the constant fails the check instead of leaving the contract and the gate disagreeing.
- `README.md`: the active backend is chosen in `/jev-eye models` rather than at login, `Models` is listed in the `/jev-eye` menu row, and a duplicated routing bullet and an unimplemented balance `"cached 5m"` claim are gone.

## [0.2.0] - 2026-10-14

### Added
- **The contract's statements are corrected, and pinned by a check.** Four statements in `REVIEW_CONTRACT` did not hold up and one language rule was stated by example: the closing line promised that code edits "will be evaluated against this turn's request text" while the gate skips any write under 10 lines (`JEV_MIN_DIFF_LINES`) and any folder the operator never granted; an absent premise (`src/eye.ts` in the session that reviewed this) had no stated handling; the language rule carried three worked examples (ID/EN/ZH) instead of one general instruction, so a reader writing another language had only inference; and the scale header was described by those same translations. All four now read as rules — the language rule names the operator's language and keeps no examples, the scale header names the axis, its range and its direction in that language, an absent premise is itself a machine fact, and the closing line states the gate's real scope. `test/contract.test.mjs` pins each one and asserts the old promise and the language examples are gone, proved negative by restoring the previous wording (the check fails). The unused `import { join }` in `review.ts` is gone too.
- `npm test` covers `review.ts`'s trigger and its contract text; the contract grew from 1753 to 1981 characters (~550 tokens) in exchange for statements that are true.
- **The reviewed turn gets a flat trigger: `/eye`.** Until now the only way in was to type the prose token `jev` or `@jev` inside the sentence, so activation depended on recalling exact syntax. `/eye <task>` opens the same contract for that turn and the task is answered normally — the write gate still compares the diff against it, and no state is added. The marker is read from the prompt text, not only from the command: pi treats input as a command only when the WHOLE text starts with `/`, so `Hai, bantu saya /eye` reaches the ordinary prompt path, where one regex catches it. The command exists because it re-sends the operator's own words — marker included — so both spellings end at that single detection point (`EYE_TRIGGER` in `extensions/review.ts`). The leading guard keeps `x/eye` and `src/eye` out, the trailing one keeps `/eyeline` and `/eye.md` out, and the prose token keeps working unchanged.
- `test/review.test.mjs`: pins the marker (six firing spellings, seven that must stay quiet, including the package's own name) and `scripts/render-check.mjs` drives the real command handler — proved negative by sending the bare task instead of the marked text, which fails the check.
- **A `Models` screen (`/jev-eye models`) chooses which backend answers.** Until now the backend was an accident of login order: `resolveJevAuth` walked `JEV_PROVIDERS` and TypeSafe won whenever two keys were stored, so the only way to make Clef the gate was to log TypeSafe out. The screen lists every backend this session can call — TypeSafe `jev-latest`, OpenRouter `typesafe/jev-1.13`, and each Clef model by tier (`clef`, `clef (flash)`) — and `[Space]` makes the highlighted row the **active** backend while `[Ctrl+f]` makes it the **fallback**. Both are saved to `~/.pi/agent/pi-jev-eye/backends.json` as `providerId:model` refs (`{ "primary": "cloudflare:clef-flash", "fallback": "typesafe:jev-latest" }`, mode 0600). The row list stays complete when a backend has no key — the row says `no key` instead of vanishing, because this screen is where an operator finds out what exists before storing a credential for it.
- **Failover behind the active backend.** `authChain` builds the order (active → fallback → the credential precedence, so a session with nothing configured still reaches whatever key it has) and `withBackends` walks it: a non-OK response, a rejected envelope, a timeout, or a network error moves to the next entry. Both the write gate and per-turn routing call the chain, so a stalled provider costs one timeout instead of losing the judgment — and `/jev-eye status` reports `N fallback` in the `Rules` row so the failover is visible rather than silent. A ref the catalog no longer lists reads as unset, so a stale or hand-edited file cannot aim the gate at a route this build cannot build.
- **The Clef model list comes from Cloudflare, not from this package — verified against the live account.** The session asks the account's Workers AI model-discovery route once (`refreshClefModels`) and caches it, so a `clef-*` model published after this release is selectable without a package update. Measured on the account that runs this machine, the route answers `["@cf/cloudflare/clef", "@cf/cloudflare/clef-omni", "@cf/cloudflare/clef-flash"]`, and `setClefModels` adds `clef-omni` to the catalog as `clef (omni)` — a model this package never shipped. A failed or absent request leaves the shipped two-model list in place, proved by clearing the cache and re-reading the catalog.
- **The footer reads `Eye: ● ON (Backend)`, with the backend the active one.** Format requested by the operator: `Eye: ● ON (Clef Flash)` for a Clef model, `Eye: ● ON (Jev)` for TypeSafe or OpenRouter. TypeSafe and OpenRouter collapse to one word on purpose — they are the same decision backend to the operator, and the footer answers "which model is judging my writes?", not "which vendor"; `/jev-eye models` is where the provider is named. The cell is `Eye:`, not a provider name, so nothing about it is hardcoded: `syncEyeStatus` reads the ACTIVE backend through `authChain(readBackends())` and re-publishes on `session_start` and every mode cycle, which means a switch in `/jev-eye models` changes this line without a reload.
- **`backendFooterName` replaces `backendDisplayName`.** The old helper returned three different shapes (`TypeSafe`, `Jev (OpenRouter)`, `Clef (flash)`) for a cell that has one line to spend; the new one returns only the suffix inside the parentheses (`Jev`, `Clef`, `Clef Flash`, `Clef Omni`) and uppercases the Clef tier so a spaced `Clef Flash` reads as one label instead of a nested `clef (flash)`. A model added upstream still needs no new case.
- **The footer draws `(…)` only when the value carries one.** `jevEyeStatusLine` in pi-arnative now parses `Eye: ● MODE (Backend)` — the label before the first colon, the backend from the trailing parentheses — and paints the suffix `dim` while `Eye:` and the state keep the soft and state tiers. An older value with no parenthesis gains no guessed one.
- `clefRowLabel`, `backendDisplayName`, `assignBackend`, `validBackendRef` in `extensions/layer1.ts`: the naming and slot-assignment folds are pure and covered by `npm test`. `assignBackend` keeps one model per slot, clears the other slot when a ref moves between them (one model can never be both the active backend and its own fallback), and treats a second press of the same slot key as a toggle.
- `modelCatalog` / `currentCatalog` / `credentialsFor` / `authFor` / `authChain` / `readBackends` in `extensions/core.ts`: the catalog is one list over every provider and every Clef model, and `credentialsFor` is now the single place the environment-versus-store precedence lives — `resolveJevAuth` walks it in provider order, so the old inline duplication is gone.
- `withBackends` in `extensions/providers.ts`: the one call path both the gate and the router take, so "which backend answered" is decided in one place.
- **`test/providers.test.mjs` drives the failover for real.** `fetch` is stubbed, the real `authChain` (against a written store and an exported key), `askJev`, `attemptJev`, `classifyWeight` and `withBackends` run, and the chain is walked: a non-OK status, a Cloudflare envelope reporting failure, an envelope with no answers, a non-JSON 200, and a thrown network error each move to the next backend; a real answer with a low score does not. This is what turned up the bug below — the failover had no behavioural test before it.

### Fixed
- **A 200 with no answer was read as a clean verdict, so the failover never ran.** Workers AI can answer `success: true` with an empty `result.answers` (a truncated or proxied response), and the old code mapped every dimension to `null` — which the gate reads as "no block signal". The attempt looked successful, `withBackends` never tried the fallback, and the write went through unjudged. An attempt now requires at least one `noul` number in `answers` before it counts as an answer; anything else is a failure of that backend and moves down the chain. Found by the new behavioural failover test, not by reading the diff.
- **A resume or a new session after `/reload` no longer leaves the status bar naming the wrong backend.** The status value was a fixed `jev-eye: ON`; it now reports the resolved backend, refreshed on `session_start` and at every mode cycle.

### Fixed
- **The advertised subcommands did not match the menu.** `EYE_SUBCOMMANDS` — the list behind `/jev-eye`'s autocomplete — promised `login`, `logout`, `on`, `review`, `off` and `toggle`, but the interactive menu has exactly four rows (`Accounts`, `Status`, `Usage`, `Routing`) and the supervisor mode is the `ctrl+shift+e` keybinding. So `/jev-eye` completed four names for one screen and four more for a mode no menu row could show, and the `routing` description advertised `light`/`heavy`/`on`/`off` values the completion engine could never reach (`getArgumentCompletions` receives everything after the command name, so typing `routing ` after the match returned an empty list and the argument had no suggestion). The list now mirrors the menu one-for-one — `accounts`, `status`, `usage`, `routing` — plus the four routing arguments that dispatch, in menu order. `scripts/render-check.mjs` asserts both directions: every advertised value dispatches instead of falling through, and no removed name is advertised. `login`/`logout` still land on Accounts, but say they were renamed instead of pretending to be distinct operations, and `/jev-eye on|review|off|toggle` names the keybinding that owns the mode instead of being reported as a typo.
- **`README` promised a `/eye` alias that was never registered.** `pi.registerCommand` is called once, for `jev-eye`, and no other command has existed in the package's history. The line is gone rather than implemented — an alias is a second name for the same handler, and this change is about removing those. The provider table and the status hints now name `/jev-eye accounts` too, so no surface still tells an operator to run a command that no longer exists.
- **The confirm dialog advertised `[←→] Switch` for a vertical list.** Every other list here moves with `[↑↓]`, and so does pi's own `ctx.ui.confirm` (it is a Yes/No select list) — but this one asked for the horizontal axis. Worse, `[←]` already means *Back* inside this extension's menus, so the footer read as "leave the dialog" in a screen where `[Esc]` is the only way out.
- **`[↑]` moved the selection down.** The two-row toggle ignored direction, so pressing Up landed on the row below. It is direction-aware and clamped now: `[↑]` at the top and `[↓]` at the bottom stay put.
- **A chosen menu row went grey on Pi 1.2.0.** Pi 1.2.0 validates a theme's `colors` with `additionalProperties: false` and rejects the whole theme if it carries an extra key, so arnative's own `accentSoft` and `tint` moved from `colors` to `vars` and `theme.fg("accentSoft", …)` now throws `Unknown theme color: accentSoft`. `chosenRowPainter` probed for it, missed, and fell through to `thinkingText` — `oklch(72% 0.012 232)`, a grey — while `pi-arnative`'s own menus stayed tinted. The soft tier is now **derived** from the resolved official token instead of substituted, using the theme generator's exact recipe (L 0.82, chroma × 0.18, hue kept), so the result is byte-for-byte the value arnative declares in `vars.accentSoft` (`oklch(82% 0.0234 218)` on `arnative.json`). Declared tokens are still probed first, so a Pi ≤1.1.0 theme renders unchanged.
- **The chosen row was not bold.** Pi-arnative paints it `soft(bold(s))`; this package painted it soft only. The soft painter is now composed with `theme.bold`, matching `/arnative` row for row.
- **The box border took the wrong tier.** `borderPainter` also probed `accentSoft` first and landed on `thinkingLow` — `oklch(55% 0.052 218)` against arnative's `accentBorder` `oklch(82% 0.078 218)` — so an arnative frame came out the wrong hue. It now derives from `borderAccent` and keeps the thinking slot only as the last resort for a theme that exposes no resolvable colour.
- **The login picker's frame was uncoloured.** `LoginPicker` read `this.paint`, a field it does not have, so the border painter was `undefined` and the frame fell back to plain text while every other screen was tinted. It now calls `borderPainterFor(t)` like its siblings — caught by rendering the real component, not by reading the diff.
- **A row could be boxed twice.** `framedRows` wrapped each row with `boxRow` and then handed it to `boxFrame`, which boxes again: every line came out three columns wide with doubled walls. Found by asserting the rendered width of the real components at 80 and 120 columns.
- **`[←] Back` was advertised on screens that could not go back.** The root menu and the Clef model picker were the first case; `/jev-eye status`, `/jev-eye usage` and `/jev-eye routing` opened straight from the command line were the second — there was no menu behind them, yet all three printed `[←] Back` and `StatusPanel.handleInput` answered `[←]` with `BACK`, which the caller dropped. All framed screens now take a `back` flag (true from the menu, false from a subcommand) that drives both the footer and whether `[←]` is handled.
- **The Clef account-id warning never appeared.** `cloudflareHint` read the v1 credential file (`{ provider, accountId }`), but the store has been `{ version: 2, providers }` since 0.1.17, so the status row explaining an unusable Cloudflare token was dead code. It now reads the v2 store through `readAuthStore` / `storedCredential`.

## [0.1.17] - 2026-10-11

### Added
- **Cloudflare Workers AI (Clef) as a third Jev provider.** `/jev-eye login` now offers `Cloudflare Workers AI (Clef)` alongside TypeSafe and OpenRouter. Clef speaks the same System One request shape (`noul` / `choice` / `score`), so the write gate, the reviewed-turn `answers_request` dimension, and per-turn routing all work against it unchanged.
- **Multi-credential auth store and a logout picker.** `auth.json` is now version 2 — a `providers` map keyed by provider id — so TypeSafe, OpenRouter and Clef can stay logged in at the same time. `/jev-eye logout` offers **Jev**, **Clef**, or **All** when several are stored; with one stored it just confirms that one. A v1 single-key file is migrated on first read and the original is kept at `auth.json.v1.bak`.
- **`/jev-eye login` shows what is already stored.** Each provider row carries its state — `✓ stored` in the theme's `success` green, or a dim `• not configured` — read from `auth.json`, so the menu answers "what am I logged in with?" before a key is typed. Choosing a provider then prints its exact key source.
- Logging in now **adds** a credential instead of replacing the file, so switching backend no longer discards the previous key. An empty key is refused rather than overwriting a good credential.
- Keys supplied by the environment are reported by logout (`$TYPESAFE_API_KEY comes from the environment and cannot be removed here.`) because a process cannot unset a variable belonging to its caller.
- A Clef credential is an account id plus a Workers AI token: the account id is asked for first (or read from `$CLOUDFLARE_ACCOUNT_ID`), then verified against the real `…/accounts/{id}/ai/run/@cf/cloudflare/clef-flash` route before anything is saved. The model is chosen at login (`clef-flash` — cheapest, the default — or `clef`).
- **Compact `/jev-eye usage` panel** that reports **Jev and Clef side by side**: requests, input tokens and cost per backend for the month, three one-line period totals (today / month / all time), and the Clef free-neuron budget — model in use, neurons spent today against the 10,000/day free allowance, a fill bar, the reset time, and the `$0.011/1,000` neuron overage once it runs out. Real spend is separated from the free tier in 18 lines instead of 22.
- **`Usage` entry in the `/jev-eye` menu.** The menu lists `Usage · Jev/Clef spend, per-provider split & free-neuron budget` next to `Status`, opening the same panel as `/jev-eye usage`.
- An **`Earlier`** row appears only when some of the period predates provider attribution, showing exactly how many requests could not be split. Without it the table would look complete while covering a fraction of the month — an error would be invisible.
- `migrateAuthStore`, `putCredential`, `removeCredentials`, `storedProviderIds` in `extensions/layer1.ts`: the store folds are pure and covered by `npm test`.
- `backendTotals` in `extensions/layer1.ts`: one pass splits a period's provider map into Clef (Cloudflare) and every other Jev provider. It normalizes each entry first, so a partially written record contributes zeros instead of poisoning the sum with `NaN`.
- `clefBody` / `clefError` in `extensions/layer1.ts`: the Workers AI route wraps the answer in `{ result, success, errors }`, and unwrapping it is now a tested pure function instead of an inline assumption.
- `cfRunUrl` / `isCloudflareAccountId`: the account id is validated (32 hex chars) before it reaches a URL, and the account-less base stays safe to commit.
- `clefUsdPerMTok`, `clefNeuronsPerMTok`, `clefNeuronsFor`, `clefBudget`, `neuronsSpentOn` in `extensions/layer1.ts`: the real per-model rates (`clef` 21,818 neurons/M, `clef-flash` 3,455, `clef-omni` 13,636) instead of one flat rate. An unknown model id is charged as the cheaper model, never as free.
- The ledger now records `providers` (a per-provider counter map) and `neurons` as optional fields, so one panel can split Jev from Clef without a second file.

### Changed
- **The login picker renders the key-source tip live.** `ctx.ui.select` paints one fixed string per row, so the tip could not follow the cursor and sat in the list as dead filler. The menu is now a small custom component (`LoginPicker`) that re-renders on every move and shows the highlighted provider's key source and environment fallback underneath the list. Headless and RPC sessions, which have no `custom` UI, keep the plain select with the same rows. The store is re-read after the picker closes, so a key added elsewhere mid-flow is still counted when deciding which backends stayed logged in.
- **`/jev-eye status` no longer carries usage.** Spend had two homes after `/jev-eye usage` shipped. Status is now a nine-line live-state view (supervisor, gate key, rules, routing, block counts, context), and the balance lookup moved to `usage` — so status is instant and never waits on a network call.
- **Discoverability:** `package.json` `description` and `keywords` now name Cloudflare Workers AI, Clef, and `clef-flash`, and the README leads with a keyword line plus a "Why Clef" section — so a search for the Clef backend surfaces this package.
- Jev providers gained a short name (`short`) for one-line rows: `Cloudflare Workers AI (Clef)` reads as `Clef` in the status line, while the login menu keeps the full label.
- A stored Cloudflare key without an account id is treated as "not logged in", so the gate says `run /jev-eye login` instead of failing every request. `/jev-eye status` explains the specific case.
- Ledger cost for Clef uses the real per-model rate (`clef-flash` `$0.038/M`, `clef` `$0.24/M`) instead of the generic TypeSafe `$0.042/M` estimate, and the balance line reports free neurons left today.
- `StatusPanel` takes an optional title and description, so `/jev-eye usage` reuses the status frame instead of duplicating it.
- `/jev-eye login` now warns before overwriting when a `$TYPESAFE_API_KEY` / `$OPENROUTER_API_KEY` / `$CLOUDFLARE_API_TOKEN` is already exported and takes precedence.

### Fixed
- **Read-only `/jev-eye usage` footer.** The panel reused the status frame, so it advertised `[Alt+Shift+j] Mode` and `[Ctrl+Shift+g] Grant folder` and acted on those keys, though a spend view has nothing to toggle. It now shows `[Enter] Done  [Esc] Cancel` and ignores the toggle keys.
